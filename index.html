Pre-launch critique

This is not a launch.

This is a small idea under pressure: can communication be built so the trusted relationship belongs first to the people, not the platform?

Status: open question

The problem

Communication tools do more than move messages.

They often hold the account, contact graph, identity layer, and much of the memory around a relationship.

Over time, the platform does not only help you communicate. It becomes the practical owner of the relationship layer.

The question

What if the relationship layer were user-controlled?

The project explores a communication environment where trusted relationships are established explicitly, represented locally, and not owned by a platform contact graph.

Principle: user-held trust

The first proof

Start smaller than the ambition.

  • Direct text communication between known peers.
  • Explicit pairing before trust is assumed.
  • Local names bound to cryptographic identities.

Planned: narrow proof point

The distinction

Not another chat app, if this works.

A normal messenger asks whether Alice can send Bob an encrypted message.

This project asks whether Alice and Bob can establish, see, preserve, and reason about their trusted relationship without a platform owning it for them.

The power shift

Architecture decides who gets practical agency.

Less of this

Platform-owned identity, hidden contact graphs, ambient data flow.

More of this

Explicit pairing, local identity, visible trust, bounded exports.

Boundaries

What this is not.

  • Not a finished product.
  • Not a mainstream messenger yet.
  • Not an AI assistant.
  • Not a claim that all infrastructure disappears.

Boundary: no overclaim

Later direction

AI belongs behind explicit data boundaries.

Later AI may become useful over communication context, but it should be local-first or explicitly user-controlled.

It should not become an invisible third-party context consumer.

Later: not part of the first proof

The ask

Help find the weak point.

What is unclear, overclaimed, too abstract, or worth proving in a first demo?
